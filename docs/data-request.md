# Seagate 无锡工厂 RAG PoC 数据申请说明

- 用途：SelfTest 或工厂确认的替代测试环节之良率异常首轮分诊 PoC
- 原则：最小必要、只读、脱敏、可追溯、限定用途、到期删除
- 配套清单：`deliverables/Seagate无锡_RAG_PoC_数据申请清单.xlsx`

> 请不要直接把敏感文件复制到本项目。应先由 Seagate 指定的数据所有者与信息安全团队确定批准的传输、存储和脱敏方式。

## 1. P0 最小样本

只有以下四组数据齐备，才建议启动检索效果评测。

### 1.1 历史异常案例：50–100 个已关闭问题

每个案例至少需要：

- 调查编号、发现时间、关闭时间；
- 产品/产品族、测试阶段、产线、站点/设备；
- 失败现象或 Failure Code；
- 异常范围：单站、多站、跨线、批次或版本集中；
- 关键检查、已排除原因；
- 最终根因类别、临时措施、永久措施、验证结果；
- 案例状态、审核人、适用条件和不适用条件；
- 与原始证据的关联 ID。

优先采用按时间切分的盲测：较早案例用于建立索引，较新案例只用于评测，避免答案泄漏。

### 1.2 制造上下文：至少 8–12 周聚合数据

建议使用小时级或事件级聚合，不申请单盘原始明细，除非现场证明聚合粒度无法支持场景。

至少包括：

- 时间窗口；
- 产品/产品族；
- 产线、站点、设备；
- 测试阶段；
- 测试量、通过量、失败量、FPY；
- Failure Code/失败模式及发生数；
- 基线或控制限；
- 物料批次；
- 测试程序与固件版本；
- 数据质量状态和来源系统。

### 1.3 权威工程文档

每一类建议提供 5–20 份脱敏样本：

- Failure Code/失败模式定义；
- 有效 SOP；
- OCAP 或异常响应流程；
- FA/8D/问题关闭报告；
- 测试程序、固件、工艺或设备变更记录；
- 设备校准/维护流程；
- 角色和升级路径。

每份文档必须附带：文档 ID、版本、状态、生效/失效日期、所有者、适用范围、密级和访问角色。

### 1.4 主数据和关联字典

- 产品、产品族与生命周期；
- 产线、站点、设备关系；
- Failure Code 和同义词；
- 物料类型、批次和供应商匿名别名；
- 测试程序和固件版本；
- 团队、角色和权限；
- 各系统主键之间的映射。

## 2. 不申请或默认删除的内容

- 员工姓名、个人联系方式、绩效或人事信息；
- 客户名称、序列号、合同或商业条款；
- 供应商真实名称，可使用稳定匿名别名；
- 密码、Token、证书、连接串和密钥；
- 未经批准的单盘序列号或可反向识别的完整追踪链；
- 与 PoC 场景无关的工艺参数和设计资料；
- 草稿、私人聊天或邮件，除非有明确的数据治理批准；
- 已超过批准留存期限的数据。

## 3. 脱敏要求

| 数据 | 建议处理 |
| --- | --- |
| 产品型号 | 保留产品族；具体型号可稳定映射为 `PRODUCT-A/B` |
| 产线/站点/设备 | 稳定映射，必须保留层级和重复关系 |
| 物料批次 | 稳定哈希或别名，保留同批次关联 |
| 供应商 | 使用 `SUPPLIER-A/B`，不保留真实名称 |
| 时间 | 可按固定偏移处理，但所有系统使用同一偏移 |
| 数量/良率 | 优先保留相对关系；若缩放，记录缩放规则 |
| 文档正文 | 删除姓名、客户、供应商、密钥和受限参数 |
| 调查结论 | 保留根因类别与证据关系，具体参数按权限处理 |

脱敏不能破坏用于检索的关键关系。例如把同一批次随机映射成不同值，会让物料集中问题无法评测。

## 4. 交付格式

优先顺序：

1. 只读数据库视图或批准的 API；
2. Parquet/CSV 结构化导出；
3. PDF、DOCX、HTML 或 TXT 文档及独立元数据表；
4. 图片型 PDF 需允许在批准环境中 OCR。

每次交付附：

- 数据所有者和审批编号；
- 导出时间与时间范围；
- 字段说明与单位；
- 脱敏规则；
- 行数、文件数和校验和；
- 密级、允许用户和到期删除日期；
- 已知质量问题。

## 5. 数据质量门槛

- 关键主键非空率 `>= 99%`；
- 跨系统关联成功率建议 `>= 95%`；
- 时间戳、时区和聚合窗口定义一致；
- 文档状态、版本和适用范围可判断；
- 已关闭案例有可审核的最终结论或明确标记为未解决；
- 不把未经审核的推测当作“确认根因”；
- 训练/索引集与盲测集按调查时间隔离；
- 所有数据都能追溯到来源系统或文件。

## 6. 安全和留存

- PoC 只在 Seagate 批准的环境运行；
- 默认禁止数据出域和未经批准的外部模型调用；
- 检索结果遵循源文档访问权限；
- 记录查询、引用、回答、反馈和权限判定日志；
- 测试结束后按批准日期删除样本和索引；
- 删除范围包括缓存、临时文件、向量索引和备份副本；
- 由数据所有者确认删除完成。

## 7. 数据到位的 Definition of Ready

只有同时满足以下条件，开发进入真实数据阶段：

- P0 清单有明确所有者和批准状态；
- 50–100 个历史问题的抽样规则已确认；
- 至少两名工程 SME 能给出独立相关性判断；
- 权威文档版本与权限元数据可用；
- 制造上下文能关联案例与文档适用范围；
- 部署、模型、日志和留存边界已批准；
- 盲测集在索引构建期间不可见。
