# Seagate 无锡工厂 RAG PoC 现场访谈脚本

- 目标：用半天工作坊把公开信息推断改成经工厂确认的需求
- 建议参与者：业务负责人、产品/性能工程、工艺/设备工程、质量/FA、GFIT/MES、信息安全/数据治理
- 建议人数：6–10 人
- 建议时长：3.5 小时

> 访谈不展示“我们已经知道答案”的姿态。SelfTest、SeaTrack 字段、角色分工和合成代码 `F127` 都是讨论起点，不是对工厂真实流程的声明。

## 1. 会前准备

请工厂准备但不要提前传输敏感材料：

- 最近 3 个已关闭的典型良率/测试异常编号；
- 当前异常调查涉及的系统名称；
- 一份可在会议室展示的脱敏 SOP 或 OCAP；
- 一份脱敏 FA/8D/问题关闭报告；
- 一个由现场工程师现场演示的真实检索过程；
- 当前权限、审计和数据出域限制。

## 2. 工作坊流程

| 时间 | 模块 | 目标 | 输出 |

## 3. 必问问题

### A. 业务与范围

1. 过去三个月最常见、最耗时或影响最大的测试/良率异常是什么？
2. SelfTest 是高价值切口吗？如果不是，应聚焦哪个测试阶段或异常类型？
3. 一次“首轮分诊”从何时开始、以什么结果结束？
4. 谁对首轮分诊负责？谁确认根因？谁批准永久措施？
5. 每月大约有多少个同类问题？高峰期同时处理多少个？
6. 哪类问题最值得复用历史经验，哪类问题每次都高度独特？

### B. 真实案例走查

1. 异常最初由哪个系统、报表或人员发现？
2. 第一位工程师当时看了哪些字段？按什么顺序？
3. 在第一个小时内查过哪些系统和文档？
4. 哪个证据最早改变了调查方向？
5. 哪些看似相似的案例后来被排除？为什么？
6. 哪个步骤等待最久：数据、权限、专家、实验还是审批？
7. 结论如何记录？其他工程师下次能否检索到？
8. 如果重新处理这次问题，哪三项信息最希望一开始就看到？

### C. SeaTrack/MES 与结构化数据

1. SeaTrack 在无锡现场承担哪些功能？哪些系统负责测试、良率、设备、批次和变更？
2. 告警或调查记录中是否已有产品、站点、设备、失败代码、物料和软件版本？
3. 数据粒度是单盘、批次、小时还是事件？PoC 允许使用哪一种？
4. Failure Code 的定义是否随产品、测试阶段或程序版本变化？
5. 是否有正常基线、控制限或异常标签？谁维护？
6. 是否能获得只读离线导出？支持 CSV、Parquet、数据库视图还是 API？
7. 哪些关键关联字段目前缺失或质量不稳定？
8. 时间戳、站点 ID、批次 ID 和版本 ID 是否能跨系统对齐？

### D. 文档与历史案例

1. 权威知识分别存放在哪里：SOP、OCAP、FA、8D、变更记录、交接记录？
2. 哪个系统是每类文档的唯一权威源？
3. 如何判断文档是草稿、有效、已替代还是已退休？
4. 文档是否包含适用产品、站点、测试阶段和版本元数据？
5. 历史问题是否记录已排除原因、最终根因、验证结果和批准人？
6. 是否允许把聊天、邮件或 Teams 消息作为线索？能否作为正式证据？
7. 哪类内容绝不能进入模型索引？
8. 谁负责修正过期文档和错误案例？

### E. 工程师体验

1. 工程师更自然的输入方式是什么：Failure Code、告警编号、自然语言还是自动带入上下文？
2. 一份可接受的回答最多有多少内容？
3. 工程师需要看到相似度分数，还是更需要看到相似/不相似条件？
4. 引用应精确到文档、章节、页码还是数据窗口？
5. 对系统建议，工程师需要接受、修改、拒绝还是转派？
6. 什么情况下系统应该直接说“不知道”并升级？
7. 在现场终端、办公室电脑还是移动设备使用？网络和响应时间要求是什么？

### F. 安全与治理

1. 产品、参数、供应商、客户测试和 FA 数据分别是什么密级？
2. 是否允许数据离开工厂网络？允许使用哪些模型和部署环境？
3. 用户权限来自哪个身份系统？文档权限能否同步？
4. 回答、检索记录、反馈和模型日志需要保留多久？
5. 哪些提示必须拒绝：改参数、跳测、放行、停线、下载受限资料？
6. 是否需要逐条显示“人做最终决定”的确认？
7. 谁负责安全测试、红队测试与上线批准？

### G. 价值与验收

1. 当前首轮分诊的中位耗时如何定义和测量？
2. “有用案例”由谁判断？如何处理专家分歧？
3. 误检和漏检哪个成本更高？
4. 引用错误、过期文档或越权暴露是否为一票否决？
5. 50–100 个历史问题能否组成盲测集？
6. 6 周结束时，谁做 Go / Adjust / Stop 决策？

## 6. 访谈结束的最低成果

- 一个经过工厂确认的一句话问题定义；
- 一张真实的当前流程图；
- 一个主场景和两个明确排除的场景；
- P0 数据与文档清单及负责人；
- 50–100 个历史问题的抽样方法；
- 安全红线与部署边界；
- 6 周 PoC 的人员、指标与决策日期。
